# 发版与下载

## 一、发布一个新版本

```powershell
Set-Location D:\github\projects\fanqie-reader-20261111

# 1. 改功能、写文档

# 2. 升版本号（三选一）
node scripts/bump-version.js patch     # 4.1.0 -> 4.1.1
node scripts/bump-version.js minor     # 4.1.0 -> 4.2.0
node scripts/bump-version.js major     # 4.1.0 -> 5.0.0

# 3. 在 CHANGELOG.md 顶部加一节
#    ## [4.1.1] - 2026-11-20
#    不写的话 CI 第一关就会红

# 4. 自检
node scripts/check.js

# 5. 提交、打标签、推
git add -A
git commit -m "4.1.1：修 xxx"
git tag -a v4.1.1 -m "v4.1.1"
git push origin main
git push origin v4.1.1
```

推 tag 之后 CI 自动跑四关：

| 关 | 做什么 | 不过会怎样 |
|---|---|---|
| `check-version` | tag 与 `VERSION` 一致、CHANGELOG 有对应小节 | 秒级报红，不产包 |
| `build` | 拉底座 → 注入资产 → 定版本 → 签名构建 arm64 + universal | 报红 |
| `verify` | `apksigner verify` + `aapt2 dump badging` + `classes.dex` 检查 | 报红 |
| `release` | 生成 SHA256、建 Release、传两个 APK | 报红 |

单次构建约 20～25 分钟（底座首次配置 + Kotlin 编译占大头）。

## 二、手动触发（不建 tag，用来验证流水线）

```powershell
$token = (("protocol=https`nhost=github.com`n`n" | git credential fill) |
          Where-Object { $_ -match '^password=' }) -replace '^password=',''
$body = '{"ref":"main","inputs":{"version":"4.1.0"}}'
curl.exe -s -X POST `
  -H "Authorization: Bearer $token" `
  -H "Accept: application/vnd.github+json" `
  -H "Content-Type: application/json" `
  --data $body `
  https://api.github.com/repos/mengxiangbaofu888/fanqie-reader-20261111/actions/workflows/release.yml/dispatches
```

注意：手动触发如果版本号与已有 Release 相同，会**覆盖**同名 Release 的附件。

## 三、产物命名

| 文件 | 内容 |
|---|---|
| `reader-fanqie-arm64-<版本>.apk` | 只含 `arm64-v8a`，约 21 MB，绝大多数手机用这个 |
| `reader-fanqie-universal-<版本>.apk` | 含 `arm64-v8a` / `armeabi-v7a` / `x86` / `x86_64`，约 27 MB，模拟器和老设备用 |
| `SHA256SUMS.txt` | 上面两个包的校验和 |

> **中文字符在附件名里会被 GitHub 吞掉**：`阅读-番茄排版-arm64-4.1.0.apk` 上传后会变成
> `-.-arm64-4.1.0.apk`，因为 GitHub 对附件 `name` 和显示名 `label` 做同一套 ASCII 清洗，
> 改哪个都一样。所以附件统一用纯英文名，中文名只出现在 Release 正文的说明里。

## 四、校验与安装

```bash
sha256sum -c SHA256SUMS.txt        # Linux/macOS
certutil -hashfile reader-fanqie-arm64-4.1.0.apk SHA256   # Windows
```

安装：

```bash
adb install -r reader-fanqie-arm64-4.1.0.apk
```

或者直接把 APK 传到手机点安装（需要允许「安装未知来源应用」）。

### 包名与覆盖升级

| 版本 | 包名 |
|---|---|
| 3.99.x / 4.00.x（早期拆包改 smali 那批） | `io.legado.app.release` |
| **4.1.0 起（源码构建）** | **`io.legato.kazusa`** |

不是一个应用，**不能覆盖安装**，会并存。想迁移的话：老版本 → 备份与恢复 → 导出书源和书架 →
新版本导入。

签名是同一把钥匙（`SHA-256 624e877f…42667f`），所以将来若把包名改回去，能覆盖 4.00.x 的老包。

## 五、本地发版（不走 CI）

```powershell
# 需要 JDK 17+21、Android SDK platforms;android-36/37 + build-tools;35/36
node scripts/prepare-base.js
node scripts/apply-patches.js
node scripts/patch-base-version.js 4.1.1
node scripts/bump-version.js 4.1.1

cd build\base\legado
.\gradlew.bat assembleAppCoreRelease --no-daemon `
  -PRELEASE_STORE_FILE="D:\github\projects\fanqie-reader-20261111\keystore\release.jks" `
  -PRELEASE_STORE_PASSWORD=legado123 -PRELEASE_KEY_ALIAS=legado -PRELEASE_KEY_PASSWORD=legado123
```

产物在 `build\base\legado\app\build\outputs\apk\appCore\release\`。

> 本机 `github.com:443` 经常连不上（只有 `api.github.com` 与 `objects.githubusercontent.com` 可达），
> 所以本地推代码走 SSH over 443：
>
> ```powershell
> $env:GIT_SSH_COMMAND = '"C:\Program Files\Git\usr\bin\ssh.exe" -i "D:\github\downloads\fanqie-reader-20261111\ssh\id_ed25519_nopass" -o IdentitiesOnly=yes -p 443'
> git remote set-url origin ssh://git@ssh.github.com:443/mengxiangbaofu888/fanqie-reader-20261111.git
> ```
