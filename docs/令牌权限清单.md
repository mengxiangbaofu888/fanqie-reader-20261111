## 三、如果要换成 Fine-grained token（更安全，推荐长期用）

GitHub 现在推荐细粒度令牌，只授这一个仓库。真要换，按这个表勾：

| 权限项 | 级别 | 为什么 |
|---|---|---|
| Repository access | `Only select repositories` → 选 `fanqie-reader-20261111` | 最小暴露面 |
| **Contents** | `Read and write` | 推代码、打 tag、建 Release、传附件 |
| **Metadata** | `Read`（必选，自动勾上） | 基础读取 |
| **Workflows** | `Read and write` | 改 `.github/workflows/` 下的文件 |
| **Actions** | `Read and write` | 触发/取消流水线、读运行结果 |
| **Secrets** | `Read and write` | 写入签名密钥与口令（`KEYSTORE_B64` 等） |
| **Variables** | `Read and write` | 版本号等非密钥变量 |
| **Pages**（可选） | `Read and write` | 只有要开下载页/教程页时才勾 |
| Issues | `Read and write`（可选） | 用 issue 报 bug 时才需要 |
| Pull requests | `Read and write`（可选） | 接受他人 PR 时才需要 |
| Administration | 不勾 | 建仓那一下用用户级令牌做完就行，之后不需要 |

> 细粒度令牌**不能**用于 `POST /user/repos`（建仓），建仓必须用用户级令牌或网页。
> 所以流程是：先用手上这个 `gho_` 建仓 → 再换细粒度令牌日常推送。

## 四、Actions 需要的仓库 Secrets

| Secret | 内容 | 怎么生成 |
|---|---|---|
| `KEYSTORE_B64` | `keystore/release.jks` 的 base64 | `[Convert]::ToBase64String([IO.File]::ReadAllBytes('keystore\release.jks'))` |
| `KEYSTORE_PASSWORD` | keystore 口令 | 自定 |
| `KEY_ALIAS` | 别名 | 自定，如 `reader` |
| `KEY_PASSWORD` | key 口令 | 自定 |

> 这四样属于**发布密钥**，一旦用来签过包就必须永久保存，丢了就无法覆盖升级老用户。
> 本仓库在 `keystore/README.md` 里写了离线备份要求。

## 五、`git push` 与 `gh` CLI

`gh` CLI 已装在 `D:\github\tools\gh\bin\gh.exe`（2.63.2），没登录也没关系，
用 `GH_TOKEN` 环境变量临时注入即可：

```powershell
$out = "protocol=https`nhost=github.com`n`n" | git credential fill
$env:GH_TOKEN = ($out | Where-Object { $_ -match '^password=' }) -replace '^password=',''
D:\github\tools\gh\bin\gh.exe repo create fanqie-reader-20261111 --public --source . --push
```

推送时 git 走凭据管理器自动带上同一个令牌，不需要在 URL 里写密码。
